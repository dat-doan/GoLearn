Go Cheatsheet: Array & Slice

Ghi nhớ nhanh đặc tính · sơ đồ bộ nhớ · ví dụ · lỗi thường gặp · best practices (Go 1.21+). Ví dụ chạy được: slice_array_examples.go

Một câu để nhớ: Array = vùng nhớ cố định, là value (gán là copy). Slice = “cửa sổ” 3 trường (ptr, len, cap) nhìn vào một array bên dưới, header được copy, dữ liệu thì chia sẻ.

1. Array: mảng kích thước cố định

var a [3]int            // [0 0 0] zero value
b := [3]int{1, 2, 3}
c := [...]string{"x", "y"}  // compiler tự đếm → [2]string
d := [5]int{1: 10, 3: 30} // [0 10 0 30 0]

Array là value type

Đặc tính ArrayHệ quả thực tế
Kích thước là một phần của type[3]int ≠ [4]int, không gán/so sánh/truyền cho nhau được
Value typeGán, truyền vào hàm, range đều copy cả mảng (mảng lớn → tốn)
So sánh đượca == b nếu phần tử comparable; dùng được làm key của map: map[[2]int]string
Kích thước là hằng số compile-time[n]int với n biến → lỗi; dùng slice
Cấp phátThường nằm trên stack (nếu không escape) → nhanh, không GC

Dùng khi: kích thước cố định, nhỏ và có ý nghĩa ([16]byte UUID, [32]byte hash, toạ độ [2]float64), cần so sánh/làm map key.

2. Slice: header 3 trường trỏ vào array

Cú pháp tạo & cắt

s1 := []int{1, 2, 3}          // literal: len=3 cap=3
s2 := make([]int, 3)         // len=3 cap=3, zero
s3 := make([]int, 0, 10)     // len=0 cap=10 (preallocate)
var s4 []int                 // nil slice
s5 := arr[1:4]                 // từ array

s[low:high]        // len=high-low, cap=cap(s)-low
s[low:high:max]    // cap = max-low (full slice expr)
s[:n]  s[n:]  s[:]
Quy tắc cắt: s[i:j] lấy [i, j) — không copy dữ liệu, chỉ tạo header mới. Chỉ số tối đa của j là cap, không phải len.

3. Chia sẻ backing array & append

3a. Cắt slice → cùng một mảng

s1[0] = 100       // arr[1] cũng thành 100
s1 = append(s1, 200) // ghi đè arr[3] = 200 !

3b. append: còn cap vs vượt cap

Sau realloc, slice cũ và slice mới không còn chung dữ liệu. Hành vi này phụ thuộc cap → đừng dựa vào nó.

Công thức tăng trưởng cap (gần đúng, Go 1.18+)

cap < 256: ×2 · cap ≥ 256: tăng dần về ~×1.25 (+192) · sau đó làm tròn theo size class của allocator. Vì vậy không nên hard-code giả định về cap.

4. API cần nhớ

Built-in

len(s)  cap(s)
s = append(s, x, y)
s = append(s, other...)
n := copy(dst, src)  // min(len)
clear(s)             // zero hoá phần tử (1.21)
for i, v := range s {}
for i := range 5 {}  // 1.22

Package slices (1.21+)

slices.Clone(s)
slices.Equal(a, b)
slices.Contains(s, x)  slices.Index(s, x)
slices.Sort(s)  slices.SortFunc(s, cmp)
slices.Reverse(s)
slices.Insert(s, i, v...)
slices.Delete(s, i, j)   // xoá [i,j)
slices.Max(s)  slices.Min(s)
slices.BinarySearch(s, x)  // s đã sort

Công thức thường dùng

// Xoá index i, giữ thứ tự
s = slices.Delete(s, i, i+1)
// Xoá index i, không giữ thứ tự (O(1))
s[i] = s[len(s)-1]; s = s[:len(s)-1]
// Chèn x vào index i
s = slices.Insert(s, i, x)
// Lọc tại chỗ (không cấp phát thêm)
out := s[:0]
for _, v := range s { if keep(v) { out = append(out, v) } }
// Pop / Push kiểu stack
top := s[len(s)-1]; s = s[:len(s)-1]
// Queue: s = s[1:]  (cẩn thận giữ mảng cũ, xem lỗi #6)

5. Lỗi thường gặp & cách tránh

#1append ghi đè dữ liệu slice khác

Cắt s[a:b] rồi append khi còn cap sẽ ghi vào phần tử kế tiếp của slice gốc.

orig := []int{1,2,3,4}
sub := orig[:2]
sub = append(sub, 99)
// orig = [1 2 99 4]  ← bị đổi!

Cách tránhDùng full slice expression orig[:2:2] (cap = 2, append sẽ realloc) hoặc slices.Clone.

#2Quên gán lại kết quả append

// ✗ caller không thấy phần tử mới
func add(s []int) { s = append(s, 4) }
// ✓ trả slice mới về
func add(s []int) []int {
    return append(s, 4)
}

Header được truyền theo giá trị, len mới chỉ nằm trong bản copy. Sửa phần tử s[0]=… thì caller thấy, append thì không.

Cách tránhLuôn s = append(s, …); hàm nhận con trỏ *[]T hoặc trả slice mới.

#3Nhầm make([]T, n) với make([]T, 0, n)

s := make([]int, 5)
s = append(s, 1)      // [0 0 0 0 0 1] — len 6!
s := make([]int, 0, 5)  // ✓ để append

Cách tránhMuốn gán theo index → make([]T, n); muốn append → make([]T, 0, n).

#4Index out of range / slice bounds panic

s := []int{1,2,3}
_ = s[3]        // panic: index out of range
_ = s[2:5]      // panic: bounds (5 > cap)
var a [3]int; i := 5; _ = a[i] // panic runtime

Cách tránhKiểm tra len trước khi truy cập; nhớ cận trên khi cắt là cap, cận index là len.

#5range cho bản copy của phần tử

for _, p := range people { p.Age++ }  // ✗ không đổi slice
for i := range people { people[i].Age++ } // ✓

Với range trên array, cả mảng cũng bị copy (trừ khi range trên &arr hoặc arr[:]).

Go < 1.22Lấy &v của biến vòng lặp luôn cùng một địa chỉ. Từ 1.22 mỗi vòng lặp có biến riêng.

#6Rò rỉ bộ nhớ: slice nhỏ giữ mảng lớn

big := make([]byte, 1<<20)
head := big[:10]       // cap vẫn là 1 MiB, GC không thu hồi
head = slices.Clone(head) // ✓ copy ra mảng nhỏ

Cũng đúng với slice chứa con trỏ: phần tử bị cắt ra khỏi len vẫn giữ tham chiếu. Gán nil/clear() phần tử cuối trước khi thu ngắn.

#7Gán slice = copy dữ liệu?

b := a        // slice: b và a cùng backing array!
b[0] = 9      // a[0] cũng thành 9
b := slices.Clone(a) // ✓ bản sao độc lập
// copy(dst, src): chỉ chép min(len(dst), len(src))
dst := []int{}; copy(dst, src) // ✗ chép 0 phần tử

Cách tránhdst := make([]T, len(src)) rồi mới copy.

#8Data race & slice 2 chiều dùng chung hàng

row := make([]int, 3)
grid := [][]int{row, row}  // ✗ 2 hàng là một
for i := range grid { grid[i] = make([]int, 3) } // ✓

append từ nhiều goroutine lên cùng slice là data race (kể cả “chỉ append”). Dùng mutex, channel, hoặc mỗi goroutine ghi vào index riêng của slice đã cấp phát sẵn.

#9nil vs rỗng: so sánh & JSON

var a []int      // nil     → JSON: null
b := []int{}    // non-nil → JSON: []
a == nil, b == nil  // true, false
len(a) == len(b)  // cả hai = 0

Cách tránhKiểm tra rỗng bằng len(s) == 0, không dùng s == nil. Nếu API cần [] trong JSON, khởi tạo []T{} tường minh.

6. Best practices

1Mặc định dùng slice, array chỉ khi cần

Array cho kích thước cố định có ý nghĩa (hash, UUID, toạ độ) hoặc làm map key. Còn lại dùng slice.

2Preallocate khi biết trước kích thước

out := make([]Result, 0, len(in))
for _, v := range in { out = append(out, f(v)) }

Tránh realloc + copy nhiều lần; giảm áp lực GC.

3Dùng var s []T cho slice rỗng ban đầu

nil slice dùng được với len, append, range, nên không cần []T{}. Hàm trả “không có kết quả” có thể trả nil.

4Hàm nhận slice: ghi rõ có sửa hay không

Nếu hàm sửa phần tử, ghi vào doc comment. Nếu trả slice mới từ input, clone khi không muốn chia sẻ bộ nhớ. Nếu hàm lưu lại slice của caller (struct field), hãy slices.Clone để tránh bị sửa từ bên ngoài.

5Dùng package slices thay vì tự viết

slices.Contains/Index/Sort/Delete/Insert/Clone/Equal đã được kiểm chứng, gọn và generic. slices.Delete còn zero phần tử đuôi (1.22+) giúp tránh giữ tham chiếu.

6Dùng full slice expression khi trả sub-slice

return s[i:j:j]  // người nhận append sẽ không ghi đè s

7Truyền array lớn bằng con trỏ hoặc slice

func f(a *[1024]int) {}  // hoặc f(a[:])

Truyền theo giá trị sẽ copy 8 KiB mỗi lần gọi.

8Đo trước khi tối ưu

Viết rõ ràng trước. Chỉ tối ưu (preallocate, tái sử dụng buffer bằng s = s[:0], sync.Pool) khi benchmark/pprof (go test -bench -benchmem) cho thấy cấp phát là điểm nghẽn. Dùng go vet và -race để bắt lỗi sớm.

7. Checklist trước khi commit

☐ Mọi append đều được gán lại (s = append(s, …))☐ make([]T, 0, n) khi định append
☐ Không dùng s == nil để kiểm tra rỗng☐ Sub-slice trả ra ngoài đã clone hoặc giới hạn cap
☐ Vòng range sửa phần tử dùng index, không dùng bản copy☐ Không append đồng thời từ nhiều goroutine
