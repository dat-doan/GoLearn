Go Cheatsheet: Generics

Ghi nhớ nhanh đặc tính · sơ đồ minh hoạ · ví dụ thực hành · lỗi thường gặp · best practices (Go 1.18+, có ghi chú tính năng 1.21 → 1.26). Ví dụ chạy được: src/generics_examples.go

Một câu để nhớ: Viết code một lần với type parameter [T C]. Constraint C là một interface mô tả tập type được phép (type set), và nó quyết định bạn được làm gì với T (+, <, ==, gọi method). Compiler kiểm tra và instantiate lúc compile, không có ép kiểu lúc chạy như any.

1. Cú pháp cốt lõi

func Map[T, U any](s []T, f func(T) U) []U {
    out := make([]U, 0, len(s))
    for _, v := range s { out = append(out, f(v)) }
    return out
}
func Filter[T any](s []T, keep func(T) bool) []T { ... }
func Reduce[T, A any](s []T, init A, f func(A, T) A) A { ... }

nums := []int{1, 2, 3, 4, 5}
Map(nums, func(n int) string { return "#" + strconv.Itoa(n) })
// [#1 #2 #3 #4 #5]   (suy luận T=int, U=string)
Filter(nums, func(n int) bool { return n%2 == 0 })  // [2 4]
Reduce(nums, 0, func(acc, n int) int { return acc + n }) // 15
Map[int, float64](nums, ...)  // chỉ định tường minh

2. Instantiation & suy luận kiểu

Một khuôn → nhiều hàm cụ thể lúc compile

Mọi kiểm tra kiểu xảy ra lúc compile: gọi Max(1, "a") sẽ báo lỗi ngay, không đợi tới lúc chạy.

Khi nào compiler suy luận được?

Type parameter chỉ xuất hiện ở kết quả thì không suy luận được: phải ghi F[T](). Có thể chỉ ghi phần đầu, phần còn lại để compiler suy ra: ParseAll[Port].

3. Constraint & type set

Constraint càng hẹp → type set càng nhỏ → bạn được làm nhiều thao tác hơn trên T. any rộng nhất nên gần như chỉ truyền/gán được.

int hay ~int?

type Number interface {
    ~int | ~int32 | ~int64 | ~float32 | ~float64  // union
}
func Sum[T Number](xs ...T) T {
    var total T              // zero value của T
    for _, x := range xs { total += x } // + hợp lệ với MỌI type trong set
    return total
}
type Celsius float64
Sum(1, 2, 3)               // 6
Sum[Celsius](36.5, 0.5)    // 37

Các dạng constraint

Interface có ~ hoặc | chỉ dùng làm constraint, không khai báo biến được. Gói golang.org/x/exp/constraints có thêm Integer, Float, Signed, Unsigned.

4. Kiểu generic (generic types)

Stack[T]

type Stack[T any] struct{ items []T }

// receiver PHẢI ghi lại [T]
func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T        // không "return nil"
        return zero, false
    }
    v := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return v, true
}

var st Stack[string]      // phải instantiate
st.Push("a")

Set[T] + iterator

type Set[T comparable] map[T]struct{}

func NewSet[T comparable](xs ...T) Set[T] {
    s := make(Set[T], len(xs))
    for _, x := range xs { s[x] = struct{}{} }
    return s
}
func (s Set[T]) Has(v T) bool { _, ok := s[v]; return ok }
func (s Set[T]) All() iter.Seq[T] { return maps.Keys(s) }

set := NewSet("go", "rust", "go")
slices.Sorted(set.All())  // [go rust]

Quy tắc của kiểu generic

  • Dùng phải có type argument: Stack[int]; riêng Stack là lỗi without instantiation.
  • Stack[int] và Stack[string] là 2 type khác nhau, không gán cho nhau.
  • Method không được có type parameter riêng: chỉ dùng T của kiểu. Cần thêm U thì viết hàm tự do func MapStack[T, U any](…).
  • Tên trong receiver có thể khác: func (s *Stack[E]) …, hoặc _ nếu không dùng.
  • Generic type alias (Go 1.24): type Dict[V any] = map[string]V.

5. Bên trong: GC shape stenciling + dictionary

Go không sinh code cho từng type (như C++), cũng không boxing hết (như Java). Các type cùng GC shape (cùng underlying type; mọi con trỏ chung một shape) dùng chung một bản code, kèm một dictionary ẩn chứa thông tin type.

Hệ quả hiệu năng

  • Type giá trị (int, float64, struct): thường nhanh ngang code viết tay, không cấp phát thêm.
  • Type con trỏ / interface: gọi method trên T phải tra dictionary → gọi gián tiếp, khó inline, có thể chậm hơn cả interface thường.
  • Binary nhỏ hơn C++ templates vì dùng chung code theo shape.
  • Không có chi phí kiểm tra kiểu lúc chạy như any + type assertion.
  • Muốn chắc chắn: go test -bench . -benchmem so sánh 3 bản generic / interface / cụ thể.
// Nhanh: T là kiểu giá trị, toán tử được inline
func Sum[T Number](xs ...T) T

// Có thể chậm: gọi method qua dictionary
func Render[T fmt.Stringer](xs []T) // với T là *Node
// → cân nhắc func Render(xs []fmt.Stringer)

7. Kỹ thuật nâng cao

7.1 S ~[]E: giữ nguyên named slice

type Names []string
func (n Names) Join() string { ... }

func CloneLoose[E any](s []E) []E { ... }
func CloneKeep[S ~[]E, E any](s S) S {
    return append(S(nil), s...)
}
CloneLoose(names) // []string → mất Join()
CloneKeep(names)  // main.Names → .Join() OK

Đây là lý do slices.Clone, slices.Sort khai báo [S ~[]E, E …].

7.2 Gọi pointer method trên T

type Setter[T any] interface {
    *T                    // PT phải là *T
    Set(s string) error   // và có method Set
}
func ParseAll[T any, PT Setter[T]](in []string) ([]T, error) {
    out := make([]T, len(in))
    for i, s := range in {
        if err := PT(&out[i]).Set(s); err != nil { return nil, err }
    }
    return out, nil
}
type Port int
func (p *Port) Set(s string) error { ... }

ParseAll[Port]([]string{"80", "443"}) // [80 443]; PT=*Port tự suy ra

7.3 Phân nhánh theo kiểu

func Describe[T any](v T) string {
    switch x := any(v).(type) {  // phải đổi sang any trước
    case int:    return "int " + strconv.Itoa(x)
    case string: return "string " + strconv.Quote(x)
    default:     return fmt.Sprintf("khác: %T", x)
    }
}

Nếu cần nhiều nhánh theo kiểu, có thể generics không phải công cụ phù hợp.

7.4 Iterator generic (Go 1.23)

func FilterSeq[T any](seq iter.Seq[T], keep func(T) bool) iter.Seq[T] {
    return func(yield func(T) bool) {
        for v := range seq {
            if keep(v) && !yield(v) { return }
        }
    }
}
for n := range FilterSeq(slices.Values(nums), func(n int) bool { return n > 2 }) {
    fmt.Print(n, " ")   // 3 4 5
}

7.5 Constraint tự tham chiếu (Go 1.26)

type Adder[A Adder[A]] interface { Add(A) A }

type Vec struct{ X, Y int }
func (v Vec) Add(o Vec) Vec { return Vec{v.X + o.X, v.Y + o.Y} }

func SumAll[A Adder[A]](xs ...A) A {
    var total A
    for _, x := range xs { total = total.Add(x) }
    return total
}
SumAll(Vec{1, 2}, Vec{3, 4}, Vec{5, 6}) // {9 12}

Trước 1.26 viết inline: [A interface{ Add(A) A }].

7.6 Generic type alias (Go 1.24)

type Dict[V any] = map[string]V
ages := Dict[int]{"An": 30}
fmt.Printf("%T", ages)  // map[string]int  (đúng là alias)

Hữu ích khi di chuyển/đổi tên kiểu generic giữa các package mà không làm gãy code cũ.

8. Ví dụ thực hành: cache an toàn đồng thời

type Cache[K comparable, V any] struct {
    mu sync.Mutex
    m  map[K]V
}

func NewCache[K comparable, V any]() *Cache[K, V] {
    return &Cache[K, V]{m: map[K]V{}}
}

func (c *Cache[K, V]) GetOrLoad(k K, load func(K) V) V {
    c.mu.Lock()
    defer c.mu.Unlock()
    if v, ok := c.m[k]; ok { return v }
    v := load(k)
    c.m[k] = v
    return v
}
// K, V chỉ xuất hiện ở kết quả → phải ghi tường minh
cache := NewCache[int, string]()

load := func(k int) string {
    fmt.Println("load", k)
    return strings.Repeat("*", k)
}
cache.GetOrLoad(3, load) // in "load 3", trả "***"
cache.GetOrLoad(3, load) // lấy từ cache, không load lại

// Cùng code, kiểu khác, vẫn type-safe:
users := NewCache[string, *User]()
u := users.GetOrLoad("an", fetchUser) // u có kiểu *User, không cần assert

So với map[any]any: không cần v.(string), không panic vì sai kiểu, IDE gợi ý đúng kiểu.

9. Lỗi hay gặp & cách tránh

Thông báo lỗi trích từ compiler Go 1.26.

1Dùng toán tử với any

func Add[T any](a, b T) T { return a + b }
// operator + not defined on a (variable of
// type T constrained by any)
func Add[T Number](a, b T) T { return a + b }

Constraint phải đảm bảo mọi type trong set hỗ trợ toán tử. == cần comparable, < cần cmp.Ordered.

2Quên ~

func F[T int](v T) T
F(MyInt(1)) // MyInt does not satisfy int
            // (possibly missing ~ for int in int)
func F[T ~int](v T) T

3Method có type parameter riêng

func (s *Stack[T]) Map[U any](f func(T) U) []U
// syntax error: method must have no type parameters
func MapStack[T, U any](s *Stack[T], f func(T) U) []U

4Không suy luận được kiểu

func Zero[T any]() T
Zero() // in call to Zero, cannot infer T
Zero[int]()

5Trả nil cho T

return nil // cannot use nil as T value in return statement
var zero T
return zero, false   // hoặc *new(T)

Trả thêm bool/error để phân biệt "không có" với zero value hợp lệ.

6Type switch trực tiếp trên T

switch v.(type) { ... }
// cannot use type switch on type parameter value v
switch x := any(v).(type) { ... }

7Truy cập field qua constraint

func GetX[T Point | Point3D](p T) int { return p.X }
// p.X undefined (type T has no field or method X)
type HasX interface{ GetX() int } // dùng method
func Use[T HasX](p T) int { return p.GetX() }

Kể cả khi mọi type trong union đều có field X, Go vẫn chưa cho truy cập.

8Chuyển kiểu khi constraint quá rộng

func ToInt[T any](v T) int { return int(v) }
// cannot convert v (... constrained by any) to type int
func ToInt[T Number](v T) int { return int(v) }

9comparable vẫn panic lúc chạy

func Equal[T comparable](a, b T) bool { return a == b }
Equal[any]([]int{1}, []int{1})
// panic: runtime error: comparing uncomparable type []int

Từ Go 1.20 interface (kể cả any) thỏa comparable, nên dynamic type không so sánh được sẽ panic. Tránh instantiate với interface khi dữ liệu có thể là slice/map/func.

10Dùng constraint làm kiểu biến

var n Number
// cannot use type Number outside a type constraint:
// interface contains type constraints
func F[T Number](n T)   // chỉ ở vị trí constraint

11Union chứa interface có method

type Bad interface{ fmt.Stringer | int }
// cannot use fmt.Stringer in union
// (fmt.Stringer contains methods)
type OK interface{ ~int; String() string } // giao, không phải hợp

12Dùng kiểu generic thiếu type argument

var s Stack
// cannot use generic type Stack[T any] without instantiation
var x Stack[int] = Stack[string]{} // ✗ 2 type khác nhau
var s Stack[int]

13Generics hoá thứ chỉ cần interface

func Write[W io.Writer](w W, b []byte) { w.Write(b) }
func Write(w io.Writer, b []byte) { w.Write(b) }

Chỉ gọi method thì interface đơn giản hơn, đọc dễ hơn, và có khi nhanh hơn (xem mục 5).

14Tham số []E làm mất named type

func Clone[E any](s []E) []E
Clone(names).Join() // ✗ []string không có Join
func Clone[S ~[]E, E any](s S) S

10. Best practices

Nên dùng generics, interface hay type cụ thể?

Gợi ý từ blog Go "When To Use Generics": nếu chỉ thấy mình đang viết any + type assertion, hoặc copy-paste cùng thuật toán cho nhiều kiểu, đó là lúc cân nhắc generics.

1. Viết code cụ thể trước, generics hoá khi đã thấy lặp lại thật (2–3 lần). Đừng bắt đầu bằng type parameter.
2. Ưu tiên stdlib: slices, maps, cmp, min/max trước khi tự viết Map/Filter/Contains.
3. Constraint hẹp nhất có thể (comparable thay any khi cần ==). Dùng ~ để chấp nhận named type.
4. Đặt tên theo quy ước: T (type chung), E (element), K/V (map), S (slice). Constraint dùng lại thì đặt tên (Number).

5. Hàm tự do > method

Method không có type parameter riêng, nên thao tác biến đổi kiểu (Map[T, U]) phải là hàm. Giữ method cho thao tác trên chính T.

6. Trả (T, bool) hoặc (T, error)

Không dùng zero value làm tín hiệu "không có", vì 0, "" có thể là dữ liệu hợp lệ.

7. S ~[]E cho hàm nhận và trả slice

Giữ nguyên named type của caller, giống cách slices làm.

8. Kiểu giá trị cho hot path

Generics với int/float64/struct rất nhanh. Với con trỏ/interface + gọi method, đo bằng benchmark trước khi khẳng định nhanh hơn.

9. Không lạm dụng any + type switch trong generic

Nếu thân hàm phân nhánh theo từng kiểu, đó là dấu hiệu nên dùng interface hoặc hàm riêng cho từng kiểu.

10. Viết test cho vài type argument

Ít nhất một kiểu giá trị, một kiểu con trỏ, một named type (type MyInt int) để bắt lỗi thiếu ~.

11. API đọc được

Nếu signature dài hơn thân hàm, hãy đơn giản hoá. Quá 2–3 type parameter thường là dấu hiệu thiết kế quá trừu tượng.

12. Tách constraint ra khai báo riêng

type Number interface{…} có tên dễ đọc và dùng lại hơn viết union inline ở mỗi hàm.
