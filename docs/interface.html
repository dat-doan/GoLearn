Một câu để nhớ: Interface là tập method (hành vi). Type nào có đủ method thì tự động thỏa mãn, không cần khai báo. Một giá trị interface là cặp (dynamic type, dynamic value), và nó chỉ bằng nil khi cả hai đều nil.

1. Khái niệm cốt lõi: thỏa mãn ngầm định

Không có từ khoá implements: có đủ method với đúng chữ ký là tự động thỏa mãn (structural typing, "duck typing" nhưng kiểm tra lúc compile).

type Speaker interface {
    Speak() string
}

type Dog struct{ Name string }
func (d Dog) Speak() string { return d.Name + ": Gâu!" }

type Robot struct{ ID int }
func (r *Robot) Speak() string { return fmt.Sprintf("R-%d: Bíp!", r.ID) }

// Kiểm tra lúc compile, không tốn gì lúc chạy
var _ Speaker = Dog{}
var _ Speaker = (*Robot)(nil)

for _, s := range []Speaker{Dog{"Rex"}, &Robot{7}} {
    fmt.Println(s.Speak()) // dynamic dispatch
}
// Rex: Gâu!
// R-7: Bíp!

2. Bên trong một interface value

s.Speak() ≈ s.tab.fun[0](s.data): tra bảng rồi gọi gián tiếp. Interface rỗng (any) dùng dạng gọn hơn eface{_type, data} vì không có method nào.

Hệ quả thực tế

  • 2 word: truyền interface rẻ như truyền 2 con trỏ.
  • Gán value → thường cấp phát heap: giá trị được copy và data trỏ tới bản copy (trừ trường hợp compiler tối ưu được, ví dụ số nhỏ, giá trị hằng hoặc con trỏ).
  • Gọi gián tiếp: khó inline. Trong vòng lặp nóng, cân nhắc dùng concrete type hoặc generics (PGO có thể devirtualize).
  • Không sửa được value bên trong: s.(Dog).Name = "x" → lỗi compile neither addressable. Muốn sửa, hãy lưu con trỏ *Dog.
d := Dog{"Rex"}
var s Speaker = d   // copy
d.Name = "Max"
fmt.Println(s.Speak())       // Rex: Gâu!  (vẫn là Rex)
fmt.Printf("%T\n", s)        // main.Dog

var z Speaker
fmt.Printf("%v %T\n", z, z)  // <nil> <nil>

3. Method set & receiver: value hay pointer?

Receiver của methodT thỏa?*T thỏa?
func (t T) M()✓✓
func (t *T) M()✗✓

Vì sao? Giá trị lưu trong interface không addressable, nên Go không thể tự lấy & để gọi pointer method. (Khi gọi trực tiếp v.M() trên biến thì Go tự thêm &v, nhưng qua interface thì không.)

var _ Speaker = Robot{}
// cannot use Robot{} as Speaker value:
// Robot does not implement Speaker
// (method Speak has pointer receiver)
var _ Speaker = &Robot{}  // ✓ dùng con trỏ

4. Bẫy kinh điển: nil interface ≠ interface chứa nil

Quy tắc: i == nil ⇔ cả dynamic type và dynamic value đều nil.

// ✗ SAI: biến kiểu cụ thể *MyErr được "đóng gói" vào error
func validate(ok bool) error {
    var p *MyErr
    if !ok { p = &MyErr{"dữ liệu sai"} }
    return p               // (*MyErr, nil) != nil
}
err := validate(true)
fmt.Println(err == nil)    // false 😱
// ✓ ĐÚNG: trả về nil tường minh
func validate(ok bool) error {
    if !ok { return &MyErr{"dữ liệu sai"} }
    return nil
}
fmt.Println(validate(true) == nil) // true

Cách tránh: hàm trả về error thì kiểu khai báo trả về luôn là error, không phải *MyErr; không trả một biến con trỏ có thể nil; dùng errors.As để lấy lỗi cụ thể.

5. Type assertion & type switch

var x any = 42
n, ok := x.(int)      // 42 true
s, ok := x.(string)   // "" false   (an toàn)
s := x.(string)       // panic: interface conversion:
                      // interface {} is int, not string

// Kiểm tra "khả năng" thay vì kiểu cụ thể:
if sw, ok := w.(io.StringWriter); ok {
    sw.WriteString("nhanh hơn")
}
func describe(v any) string {
    switch x := v.(type) {
    case nil:
        return "nil"
    case int, int64:     // nhiều type → x vẫn là any
        return fmt.Sprintf("số nguyên %v", x)
    case string:         // x là string
        return fmt.Sprintf("chuỗi dài %d", len(x))
    case error:          // interface cụ thể trước
        return "error: " + x.Error()
    case Speaker:
        return "biết nói -> " + x.Speak()
    default:
        return fmt.Sprintf("không rõ (%T)", x)
    }
}
  • case được xét từ trên xuống, khớp case đầu tiên. Đặt interface hẹp/cụ thể trước interface rộng.
  • .(type) chỉ dùng được trong switch.
  • Type switch nhiều nhánh thường là dấu hiệu nên chuyển sang method trên interface (đa hình).

6. Embedding: ghép interface nhỏ thành lớn

type ReadWriter interface {
    Reader   // nhúng interface = gộp method set
    Writer
}
// Trùng tên method có cùng chữ ký: được phép (Go 1.14+)

Nhúng interface vào struct: override một phần

type loudSpeaker struct {
    Speaker              // ủy quyền mọi method
}
func (l loudSpeaker) Speak() string {
    return strings.ToUpper(l.Speaker.Speak())
}

loudSpeaker{Dog{"Rex"}}.Speak() // REX: GÂU!
loudSpeaker{}.Speak()           // 💥 panic: Speaker nil

Hay dùng để bọc (decorator) hoặc tạo fake chỉ implement vài method của interface lớn. Cẩn thận method nào chưa override mà field nhúng nil thì gọi vào sẽ panic.

7. any, so sánh interface, interface trong generics

any = interface{}

Mọi type đều thỏa (method set rỗng). Mất type safety, phải assertion để dùng lại.

var v any = []int{1, 2}
v = "giờ là string"   // OK
// v + "x"            // ✗ không compile

Dùng khi: thực sự không biết kiểu (JSON động, fmt.Println, context value). Tránh khi: generics làm được (container, thuật toán).

So sánh ==

any(1) == any(1)          // true
any(1) == any(int64(1)) // false
any(Dog{"Rex"}) == any(Dog{"Rex"})
                          // true

a, b := any([]int{1}), any([]int{1})
a == b  // 💥 panic: comparing
        //    uncomparable type []int
m := map[any]int{}
m[[]int{1}] = 1 // 💥 panic: unhashable

Compile vẫn qua, lỗi chỉ xuất hiện lúc chạy.

Interface làm constraint (type set)

type Number interface {
    // ~int: mọi type có kiểu gốc int
    ~int | ~int64 | ~float64
}
func Sum[T Number](xs []T) T {
    var t T
    for _, x := range xs { t += x }
    return t
}
Sum([]Celsius{10, 20.5}) // 30.5°C

var n Number // ✗ cannot use type Number
             // outside a type constraint

9. Ví dụ thực hành

9.1 Interface phía consumer + fake để test (Dependency Injection)

store không import greet, cũng không cần biết UserGetter. greet chỉ phụ thuộc đúng 1 method nó cần → dễ thay thế, dễ test, không vòng import.

// package greet: khai báo ĐÚNG thứ mình cần
type UserGetter interface {
    GetUser(id int) (User, error)
}

type Greeter struct{ users UserGetter }

func (g Greeter) Greet(id int) string {
    u, err := g.users.GetUser(id)
    if errors.Is(err, ErrNotFound) { return "Xin chào người lạ" }
    if err != nil { return "lỗi: " + err.Error() }
    return "Xin chào " + u.Name
}

// main: lắp ráp
Greeter{store.NewMemStore()}.Greet(1)  // Xin chào An

// greet_test.go: fake không cần mock framework
type fakeUsers map[int]User
func (f fakeUsers) GetUser(id int) (User, error) {
    if u, ok := f[id]; ok { return u, nil }
    return User{}, ErrNotFound
}
Greeter{fakeUsers{5: {5, "Bình"}}}.Greet(5) // Xin chào Bình

9.2 Func adapter (mẫu http.HandlerFunc)

type Handler interface{ Handle(msg string) string }

// Một kiểu hàm cũng có method → thỏa interface
type HandlerFunc func(string) string
func (f HandlerFunc) Handle(m string) string { return f(m) }

func logging(next Handler) Handler {   // middleware
    return HandlerFunc(func(m string) string {
        fmt.Println("[log] nhận:", m)
        return next.Handle(m)
    })
}

echo := HandlerFunc(func(m string) string { return "echo " + m })
logging(echo).Handle("ping")
// [log] nhận: ping → "echo ping"

9.3 Tự viết io.Writer & nâng cấp tùy chọn

type upperWriter struct{ w io.Writer }
func (u upperWriter) Write(p []byte) (int, error) {
    return u.w.Write(bytes.ToUpper(p))
}
// Chạy được với MỌI hàm nhận io.Writer / io.Reader
io.Copy(upperWriter{os.Stdout}, strings.NewReader("hello\n"))
// HELLO

// Optional interface: kiểm tra khả năng mở rộng lúc chạy
_, ok := w.(io.StringWriter)
// *os.File: true · *strings.Builder: true · upperWriter: false

Stdlib dùng mẫu này rất nhiều: io.WriterTo, io.ReaderFrom, http.Flusher.

10. Lỗi hay gặp & cách tránh

1Typed nil làm err != nil

var p *MyErr = nil
return p   // error(*MyErr, nil) != nil
return nil // trả nil tường minh

Xem mục 4. Kiểu trả về luôn là error.

2Pointer receiver nhưng gán value

func (r *Robot) Speak() string
var s Speaker = Robot{} // ✗ compile error
var s Speaker = &Robot{}

Thống nhất receiver: một method dùng pointer thì để tất cả dùng pointer.

3Type assertion không có ok

name := v.(string) // panic nếu v không phải string
name, ok := v.(string)
if !ok { return fmt.Errorf("cần string, nhận %T", v) }

4Con trỏ tới interface

func Run(s *Speaker) { s.Speak() }
// p.Speak undefined (type *Speaker is
// pointer to interface, not interface)
func Run(s Speaker) { s.Speak() }

Interface đã chứa con trỏ bên trong; hầu như không bao giờ cần *I.

5[]T không tự chuyển thành []I

var ss []Speaker = dogs // ✗ cannot use []Dog as []Speaker
ss := make([]Speaker, len(dogs))
for i, d := range dogs { ss[i] = d }

Bộ nhớ khác nhau: mỗi phần tử []Speaker là 2 word. Hoặc viết hàm generic func F[T Speaker](xs []T).

6So sánh / map key với type không so sánh được

any([]int{1}) == any([]int{1}) // panic
map[any]bool{}[[]int{1}] = true // panic

Tránh: chỉ dùng == / map key khi chắc dynamic type comparable; hoặc dùng constraint comparable trong generics để compiler kiểm tra.

7Tưởng sửa được giá trị qua interface

var s Speaker = Dog{"Rex"}
s.(Dog).Name = "Max" // ✗ neither addressable
var s Speaker = &Dog{"Rex"}
s.(*Dog).Name = "Max" // ✓ sửa qua con trỏ

8String() đệ quy vô hạn

func (c Celsius) String() string {
    return fmt.Sprint(c) // gọi lại String() → stack overflow
}
return fmt.Sprintf("%.1f°C", float64(c)) // ép về kiểu gốc

9Field interface nhúng để nil

type loud struct{ Speaker }
loud{}.Speak() // panic: nil pointer dereference

Tránh: dùng constructor bắt buộc truyền dependency; kiểm tra nil trong constructor.

10Interface pollution (Java-style)

// package store
type UserStore interface { /* 15 method */ }
type userStore struct{...}
func New() UserStore { return &userStore{} }
func New() *Store { return &Store{} } // trả struct
// consumer tự định nghĩa interface nhỏ nó cần

Interface lớn, khai báo sẵn ở producer, chỉ 1 implementation: khó mở rộng, khó fake, giấu mất method mới.

11Thứ tự case trong type switch

switch v.(type) {
case fmt.Stringer: ... // lỗi có cả String() → rơi vào đây
case error:        ... // không bao giờ tới
}

Tránh: đặt case cụ thể (concrete type, interface hẹp) lên trước.

12Lạm dụng any

func Max(a, b any) any // mất type safety, phải assert
func Max[T cmp.Ordered](a, b T) T // hoặc dùng built-in max()

11. Best practices

Có nên tạo interface?

“The bigger the interface, the weaker the abstraction.” (Rob Pike, Go Proverbs)
1. Accept interfaces, return structs. Tham số nhận interface (linh hoạt cho caller); giá trị trả về là kiểu cụ thể (caller dùng được mọi method, không bị bẫy typed nil).
2. Khai báo interface ở phía consumer, không phải nơi implement. Package dùng gì thì khai báo đúng cái đó.
3. Nhỏ và đặt tên theo hành vi: Reader, Notifier, UserGetter. Interface 1 method đặt tên Method + er.
4. Discover, đừng design trước: viết code cụ thể trước, tách interface khi xuất hiện nhu cầu thật (implementation thứ 2, cần fake test).

5. Assertion lúc compile

var _ http.Handler = (*Server)(nil)
var _ io.ReadWriter = (*Buffer)(nil)

Gãy build ngay khi đổi chữ ký method, thay vì lỗi ở nơi xa.

6. Lỗi: nil tường minh + errors.Is/As

var nf *NotFoundError
if errors.As(err, &nf) { ... }
if errors.Is(err, ErrNotFound) { ... }

Không so sánh err.Error() bằng chuỗi; không trả typed nil.

7. Generics thay cho any

Container, thuật toán dùng type parameter: giữ type safety, không cần assertion. any chỉ cho dữ liệu thực sự động.

8. Optional interface

Giữ interface chính tối giản; năng lực bổ sung kiểm tra bằng assertion: if f, ok := w.(http.Flusher); ok { f.Flush() }.

9. Func adapter cho interface 1 method

Cung cấp XxxFunc như http.HandlerFunc để caller truyền closure, không phải tạo struct.

10. Thống nhất receiver

Struct có state/mutex hoặc lớn → pointer receiver cho tất cả method. Kiểu nhỏ, bất biến (time.Time, Celsius) → value receiver.

11. Ghi tài liệu cho contract

Chữ ký chưa đủ: mô tả hành vi khi lỗi, có an toàn đồng thời không, ai sở hữu buffer. Ví dụ doc của io.Reader nói rõ được phép trả n > 0 cùng err.

12. Chú ý hiệu năng ở hot path

Interface = gọi gián tiếp + có thể cấp phát. Đo bằng go test -bench, -gcflags=-m (escape analysis) trước khi tối ưu; PGO có thể devirtualize.
